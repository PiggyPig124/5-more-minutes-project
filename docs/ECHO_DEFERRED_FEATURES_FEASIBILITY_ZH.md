# Echo 暂缓功能可行性与分阶段方案

**研究日期：**2026 年 9 月 28 日。**用途：**为产品团队决定 MVP 边界、技术试点和合作依赖提供依据。本文件是研究建议，不代表服务商合作、生产接入或法律结论。

## 结论先行

Echo 当前最值得继续投入的是已经验证的主线：游客提问、长者逐条确认记忆、使用已确认信息寻找有来源的社区活动，并由长者决定是否联系真人。粤语语音适合做限定样本的可用性试点；社区网页检索可以继续扩展可信来源。实时 API、跨用户匹配、推送、社工直接发送和公共故事发布都有额外依赖，不应写成已交付。打字、来源链接、人工核实及明确失败提示应始终可用。

| 项目 | 当前建议 | 进入下一阶段的条件 |
| --- | --- | --- |
| 粤语 ASR 与 TTS | 有条件试点，打字保持完整路径 | 官方语言与地区支持确认；长者声音测试、端到端延迟和成本达到团队门槛 |
| 社区来源 | 扩大限定网站自动检索，优先机构许可的结构化数据 | 来源授权与稳定性确认；来源、检索时间、失败回退和过期剔除可验证 |
| 真实用户匹配 | 暂缓 | 身份、同意、未成年人及弱势保护、举报、纠纷和组织运营机制具备 |
| 推送提醒 | 只评估自愿开启、可撤销的计划提醒 | 产品内计划与权限流程完成；通知送达与关闭行为实测 |
| 社工直接发送 | 暂缓，先提供经核实的联系路径 | 有真实合作方、正式接收方式、逐次确认及送达反馈 |
| 公共地图、故事、互助 | 暂缓公开发布 | 审核、举报、位置保护、撤回及运营责任明确 |
| 每日问候 | 排在核心记忆和社区之后 | 仅由已确认偏好或计划触发，自愿开启，可随时停止 |

## 当前代码与需求边界

已实现的社区检索只访问[香港基督教培道联爱会活动页](https://hkcmis.com/embed?unit_id=3)和[赛马会众心行善平台机会页](https://www.jcvtplatform.hk/zh/volunteer-opportunities)两个指定公开页面。按需获取，15 分钟缓存，失败时最多使用 6 小时内旧缓存并显示状态；它不是合作方实时 feed，也不确认名额或资格。缓存只保存公开结果，不向来源网站发送身份、完整记忆或会话。现有游客会话在进程内保存，30 分钟无活动后失效。默认对话仍为演示适配器；目前没有粤语 ASR/TTS、推送、社工发送或公共地图的生产接入。

SRS v1.1 第 15–18 节要求先验证 API、许可、可靠性和所需凭据，再冻结范围；隐私默认或对外发送行为变更须按需求变更流程记录。以下方案据此把每个外部能力拆成“研究、受控试点、可验收发布”。

## 粤语语音

**可行性。**[Azure Speech 官方语言表](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support)明确列出 `zh-HK` 粤语识别和三种香港粤语合成声线；[Google Speech to Text V2](https://docs.cloud.google.com/speech-to-text/docs/speech-to-text-supported-languages)列出 `yue-Hant-HK`，[Google Text to Speech](https://docs.cloud.google.com/text-to-speech/docs/list-voices-and-types)列出 `yue-HK` 声线。这证明可采购相应接口，不证明其对香港长者、助听器环境或日常家居噪声已达标。AWS [Transcribe](https://docs.aws.amazon.com/transcribe/latest/dg/supported-languages.html)可作识别备选，但 [Polly 语言表](https://docs.aws.amazon.com/polly/latest/dg/supported-languages.html)没有同样明确的香港粤语合成组合，本轮不列为首选端到端方案。

**试点做法。**先做“按住说话或明确开始录音 → 显示可编辑转写 → 用户确认后发送”，回答仍先显示文字，朗读由用户选择。音频默认不写入 Echo 的长期数据库、日志或 Memory；候选记忆仍须单独确认。以 Azure 和 Google 各做一条原型，20–30 名自愿参与的香港粤语长者，用真实 Android 设备在安静及普通家居噪声下测试短答、人物地点、日期金额和否定句；研究录音另行取得同意并定删除日。不要采集真实病历或家庭秘密来测识别。

**建议验收门槛，尚未实测。**人工审校参考转录的整体字错率不高于 15%；人名、地点、时间、金额、否定等关键字段错误不高于 5%；纠正或重录后完成任务比例至少 90%。长者对合成语音清晰度和自然度各给 5 分制至少 4 分，关键信息理解率至少 90%。在香港 Wi-Fi 与 4G 分别记录端到端 p50/p95；建议停录至最终转写 p95 不超过 2 秒、文字产生至首段可听语音 p95 不超过 1.5 秒。任一失败必须能立即改打字。这些数字是团队试验门槛，不是供应商保证。

**成本与隐私。**按使用量建模：每月识别音频分钟数 = 月活用户数 × 每人回合数 × 每回合说话秒数 ÷ 60；合成成本再按计费字符数计算。供应商价格随区域、模型和免费额度变化，签订预算前以 [Azure 价格页](https://azure.microsoft.com/en-us/pricing/details/speech/)、[Google STT 价格页](https://cloud.google.com/speech-to-text/pricing)及 [Google TTS 价格页](https://cloud.google.com/text-to-speech/pricing)按实际 SKU 核价。Azure 的[识别数据处理说明](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/speech-service/speech-to-text/data-privacy-security)和[合成数据说明](https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/speech-service/text-to-speech/data-privacy-security)可作为供应商审查起点；Echo 自己仍须规定转写、日志和评测录音的保留及删除。区域、跨境处理、合同和真实延迟须在选型前复核。

## 社区来源、匹配、推送和社工转介

**来源风险与当前控制。**[赛马会众心行善平台条款第 3.3(e) 项及第 10.1 项](https://www.jcvtplatform.hk/en/terms-conditions)明确限制未经提供方支持的接口抓取或搜索，以及未经书面授权的内容复制和再分发。技术验收曾证明“能获取”，不能证明“获准再利用”。默认应用现已停用该适配器的自动抓取与展示；取得书面授权或获提供方认可的公开接口后才能启用。用户仍可自行打开官方网页。[平台 FAQ](https://www.jcvtplatform.hk/zh/faq)还说明实际机会来自伙伴配对平台，最终报名及余位须到相关平台核实。

[HKCMIS 活动页面](https://hkcmis.com/embed?unit_id=3)目前可公开读取，但本轮未查到公开 API 文档或明确的自动抓取与再发布许可。团队应向机构确认可用字段、署名方式、访问频率、缓存时长和报名链接规则；未确认前不要把它称为获授权的 feed。香港政府 [EventHK 数据集](https://data.gov.hk/en-data/dataset/hk-dpo-mobileapps-eventhk-information)虽列出 JSON API，但页面注明自 2026 年 6 月 8 日起不再更新，因此不能作为实时活动来源。社署的[服务资料下载区](https://www.swd.gov.hk/en/svcdesk/download/listofserv/)可供核对长者中心联系路径，不等于活动名额或自动转介接口。

**来源接入规则。**为每个网站建立来源登记：主体、主题、官方页面或 API、许可/条款及查验日期、可展示字段、署名方式、访问频率、缓存期限、机构联系人、解析测试和退出方式。系统负责定时/按需抓取获准内容、检查活动日期、记录来源时间并在故障时显式降级；人只维护可信来源名单、许可和适配器，不逐条抄录活动。建议以 30 日试运行记录成功率与结构变更，按来源抽查 30–50 条标题、时间、地点、报名路径；达到团队预设精确度门槛后再对外宣称自动搜索。即使接口存在，也不得把“列出”写成“有名额”“已报名”或“获机构推荐”。

**真实匹配。**当前功能仅用本人确认技能生成一般主题，在本地过滤公开机会；它不是长者之间的互配。后续若要人与人匹配，需要身份核验、可见范围、邀请与拒绝、举报及防骚扰、组织运营和独立共享同意。先在经授权的结构化机会资料上用合成资料做离线匹配评估，再请长者逐次决定是否表达兴趣；MVP 保留官方报名链接即可。

**推送。**[Firebase Cloud Messaging 的 Flutter 文档](https://firebase.google.com/docs/cloud-messaging/flutter/receive-messages)提供 Android 等平台接收路径，[Web 文档](https://firebase.google.com/docs/cloud-messaging/web/get-started)要求 HTTPS、浏览器许可和 Service Worker。可接入不等于一定送达，离线、系统停用、权限撤销及消息过期都会影响实际体验；[FCM 生命周期说明](https://firebase.google.com/docs/cloud-messaging/customize-messages/setting-message-lifespan)应纳入测试。建议先做应用内的自愿计划提醒，再考虑设备本地通知和跨设备推送。试点必须让长者选类别、频率和勿扰时间；锁屏文字不暴露记忆或健康细节，一键关闭时删除待发任务和设备 token。测试 Android 13 及以上、离线、强停和 Web 撤权等情况，不把“平台接受消息”当作“用户收到”。

**社工或机构直发。**本轮没有核实到可供 Echo 使用的直接转介 API 或合作协议。MVP 应显示经核实的机构、联系方式和下一步，让长者自己选择联系。若未来试点，先签合作安排，明确接收人、最少字段、留存、误送与响应时限；每次发送前展示完整内容和具体收件人，由长者逐次确认，并回报真实送达状态。记忆同意不能替代对外披露同意；香港私隐专员公署的[个人资料用途原则说明](https://www.pcpd.org.hk/english/faqs/faqs.html)是进一步审查依据。

## 公共内容、提醒和保留期限

**公共地图、故事和互助。**目前故事是长者本人可见的私人卡片，代码没有公开可见范围、地图定位、审核、举报或下架流程。SRS 把互助发布列为未来范围，公共地图须先具备审核、举报和位置保护。建议不在 MVP 放可操作的公开发布按钮。未来小规模试点要逐篇确认发布、默认私密、只显示用户确认的社区或地标而非精确住所、去除图片位置元数据、发布前人工审核；建立举报、封禁、申诉、紧急处置和撤回后从搜索及缓存下架的责任人与时限。先用虚构资料做封闭试点，通过隐私影响评估和撤回演练后再考虑公开；可参照香港私隐专员公署的[私隐影响评估资料](https://www.pcpd.org.hk/english/resources_centre/publications/files/InfoLeaflet_PIA_ENG_web.pdf)。

**每日问候和提醒。**按 SRS 的 FR CON 02–04，只有长者主动开启后才能问候；不回答也不自动报告给家人。个性化原因只能来自已确认且有效的记忆或本人计划，不能使用拒绝或删除内容。计划提醒的确认画面要列出事件、时间、提醒方式和任何接收人。现代码有经确认的任务基础，但没有定时调度或推送送达实现。建议先在应用内做一个由长者创建的计划提醒，提供暂停和勿扰，取消后撤回待发通知；每日主动问候再经过小规模可用性试验确定频率。[Android 通知授权](https://developer.android.com/develop/ui/compose/notifications/notification-permission)及 [Apple 通知授权](https://developer.apple.com/documentation/UserNotifications/asking-permission-to-use-notifications)都必须按平台实际路径测试。

**保留期限建议，待团队确认，不是法律规定。**香港私隐专员公署的[删除与匿名化指引](https://www.pcpd.org.hk/english/resources_centre/publications/files/erasure_e.pdf)要求按用途确定期限，并有各类资料的保留和删除政策；未给 Echo 一个统一天数。建议先建立数据登记表：游客会话沿用现有 30 分钟无活动过期；评测录音在分析完成后例如 30 日内删除；未提交草稿仅本机短暂保存；已确认记忆由长者主动管理并在注销或删除时阻断使用、安排主库及备份处理；已完成计划、家庭消息、公开内容审核记录分别拟定目的与删期。30 日、90 日、12 个月等若要采用，只能作为产品假设由隐私、技术和产品团队审定。删除流程必须覆盖数据库、向量、缓存、日志、备份和供应商，留下不含个人内容的删除执行记录。

## 需要团队决定的事项

**建议执行顺序与责任。**默认应用已停用未获准来源的自动抓取与展示，并需用合成资料验证无结果时的官方链接路径；产品/来源负责人仍须取得 HKCMIS 许可及 JCVTP 合作答复。随后由语音负责人做两家供应商的小样本盲测和按实际 SKU 核价；由产品和隐私负责人确定保留登记、问候同意文案和演示脚本。只有来源权利与数据质量门槛通过，才增加新的自动来源；只有长者实测和隐私评审通过，才决定语音、通知或公开内容是否进入下一里程碑。

1. **可信来源清单。**先由产品与研究团队批准机构、主题、资料权利和复核频率；开发团队维护网站适配器及来源状态。AI 可自动读取活动，但不得自行把新网站加入可信清单。
2. **数据保留与删除。**先给各类数据拟定期限、删除触发和备份处理，再由产品、技术和隐私负责人共同确认；不能把游客 30 分钟过期误写成所有账户数据的保留政策。
3. **演示场景。**优先展示不注册问问题、明确开启记忆并确认一项虚构经历、由确认技能搜索经许可的真实社区来源、查看来源与不确定信息。来源许可解决前，义工环节只打开官方网页或使用明确标注的合成数据。尚未实现的 Answer Card、逐次家庭分享或语音不得录成“已完成”流程。
4. **变更记录。**涉及默认同意、共享范围、外发收件人或公开发布时，记录 SRS 需求编号、拟议变更、理由、隐私影响、开发与测试影响、MVP 或未来范围，并重新评审验收场景。

**评审记录模板。**每项决定写明：需求编号；当前行为；拟议行为；触发原因与证据链接；受影响人群与资料流；权限/保留/供应商影响；设计和开发成本；新增及回归测试；负责人和审批人；回滚办法；决定日期和适用版本。先经产品、技术和隐私/保障责任人确认，再更新 SRS 与演示材料。这是项目流程建议，落实 SRS 第 18 节的变更要求。
