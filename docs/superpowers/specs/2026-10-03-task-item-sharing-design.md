# Echo 家庭任务逐项分享设计

日期：2026-10-03
状态：已获用户授权并实施；本地回归完成，待独立复审、PostgreSQL 和真机验证。
范围：现有任务创建、家庭任务读取、撤销和提醒的权限修正。自动偏好记忆、活动目录修复、陪同回复、新通知渠道均不属于本批。

## 1. 目标、依据和现状风险

目标：长者确认创建的是私人任务；只有本人逐项选择有效家庭收件人、看见确切内容并确认后，指定照顾者才能读取该任务。care_tasks 是家庭连接层的资格，绝不是某个任务的分享同意。

依据：SRS v1.1 Corrected §8.4、FR FAM 02/03/05/06、§10.2/10.3、§12.1、AT 05。FR FAM 03 要求发送前展示选中内容和收件人；§10.3 要求撤销停止未来访问；SRS 未明确授权照顾者修改长者任务。本批采用只读，照顾者回复/标记完成的产品规则列为后续待决，不能沿用旧宽权限。

实施前结构（用于说明原始风险）：
- backend/app/models.py 的 Task 无收件人、分享状态或逐项同意记录。
- routers/actions.py 的 confirm_action 仅确认创建任务，没有选择家庭收件人。
- routers/tasks.py 的 list_tasks、_can_access_task 和 patch_task 依赖 linked_elder_ids；有效 care_tasks 连接可读取长者全部任务，并修改标题、正文、日期和状态。
- care_service.py 的 collect_notifications、visible 对任务提醒使用相同连接级权限。
- app/lib/src/app.dart 的 TaskTile 和照顾者首页把这些任务称为“已分享”，与实际记录不一致。
- backend/tests/test_integration.py 的 test_family_scope_and_revoke_are_enforced 明确期望确认任务后照顾者立即看到，须替换该旧预期，而非保留成兼容条件。

## 2. 方案选择与改动性质

推荐新增 TaskShare 关系表，复用 Task、FamilyLink、既有确认创建和提醒链路。任务本体仍只属本人；授权谓词集中用于列表、详情、提醒和通知操作。

备选：
1. 仅在客户端隐藏任务：无法约束 API、通知和旧客户端，拒绝。
2. 在 Task JSON 中放收件人：可减少表数，但不利于逐条同意、不可复活撤销、重试和并发约束，拒绝。
3. 独立 TaskShare：清楚表达逐项授权与历史，推荐。

这是小范围现有流程修正，同时包含局部数据模型和接口契约变更；不是新协作平台或新架构替换。影响集中在任务授权、提醒和对应 UI，无需重做账户、私聊、记忆、家庭消息、群聊或引入共享 broker。但不能把它视为仅改一个过滤条件：迁移、并发撤销、历史重试和客户端缓存均须一并处理。

## 3. 权限和字段边界

| 行为 | 任务本人 | 指定照顾者 | 其他照顾者/游客 |
|---|---|---|---|
| 创建、查看自己的任务 | 允许 | 仅允许其自己拥有的任务 | 仅允许登录账户自己的任务 |
| 编辑长者任务内容、日期、状态 | 允许 | 拒绝；后续另定协作权限 | 拒绝 |
| 查看长者任务 | 允许 | 满足有效逐项授权时只读 | 拒绝 |
| 创建、撤销逐项授权 | 本批仅长者任务本人允许 | 拒绝 | 拒绝 |
| 接收任务提醒 | 本人按自己的提醒设置 | 有效逐项授权且本人选择任务提醒 | 拒绝 |

有效逐项读取必须同时满足：TaskShare 未撤销、Task 存在且归属该长者、FamilyLink 当前 active 且含 care_tasks、link.caregiver_id 等于访问账户、share 内容指纹与当前任务一致。所有入口使用同一判断；禁止“连接有效则兜底允许”。

照顾者只收到 task_id、share_id、长者显示名、预览确认的 task_type/title/description/due_at，以及本人维护的当前任务进度。不得返回 source_action_id、源 conversation_id、聊天内容、记忆引用或其他任务。task_id 是授权对象标识，不能反向授予源对象访问。日期明确按香港时间展示。

正文、标题、任务类型、日期变化会撤销全部旧分享；本人仍能编辑，照顾者须等重新确认分享。单纯任务进度变化可在已分享卡显示，本批预览说明“可查看我之后更新的任务进度”，但不能授予照顾者进度修改权。

## 4. 数据模型和接口

新增 task_shares，不删除或重写现有 Task、FamilyLink：
- id、task_id、family_link_id、shared_by；外键约束。
- content_hash：服务端以规范化 task_type/title/description/due_at 计算 SHA-256；不包含状态、updated_at 或私聊标识。
- idempotency_key、request_hash：记录本人此次确认操作及其规范化请求，unique(shared_by, idempotency_key)。
- consented_at、revoked_at、revocation_reason。
- 同一 task_id/family_link_id 仅允许一个未撤销授权；SQLite/PostgreSQL 使用对应的部分唯一索引。撤销记录保留且不复活，重新分享创建新 ID。

建议接口：
- GET /tasks：本人任务与照顾者有效逐项授权任务；owner_id 过滤不能扩大权限。无该长者有效授权时过滤请求返回不披露任务存在性的 404。
- GET /tasks/{task_id}：相同授权判断；照顾者响应为上述最小只读视图。
- GET /tasks/{task_id}/shares：仅本人查看当前/已撤销收件人记录，不向照顾者暴露其他收件人。
- POST /tasks/{task_id}/shares：仅长者本人；必填 family_link_id、expected_content_hash、idempotency_key。服务端取当前任务内容，绝不信任客户端提交的副本。UI 预览所用指纹由本人任务响应提供。
- DELETE /tasks/{task_id}/shares/{share_id}：仅本人，重复撤销幂等。
- PATCH /tasks/{task_id}：本人修改；照顾者对他人任务一律拒绝，包括仅改 status。schema 拒绝额外字段。自身任务的现有行为保留。

一个确认操作对应一个收件人；本批不做默认全选、多收件人批量授权或后台自动分享。创建任务 API 不接受收件人，不产生 TaskShare，不发送家庭消息。share 接口成功意味着“已授予站内查看权限”，不意味着送达、已读、短信/推送或对方已接受任务。

错误：指纹过期 409，展示当前任务并要求重新预览；连接撤销/缺 scope 或无资格 403，不返回任务正文；隐藏对象 404；参数非法 422；重试键不同请求 409；服务失败保留预览且不显示成功。

## 5. 幂等、并发和撤销

share 操作事务内按一致顺序锁任务拥有者 Account → FamilyLink → Task → TaskShare，并重新校验角色、链接、归属、指纹和活动授权。SQLite 使用现有 BEGIN IMMEDIATE 模式；PostgreSQL 使用行锁。相关任务编辑、连接撤销、share 撤销、未来 scope 变更采用一致锁序，避免旧授权在竞态中通过。

同键同请求返回同一 share_id；同键不同任务/链接/指纹拒绝。已有同对象有效授权返回原授权，不重复创建。命中旧键前仍复核授权；若原授权已撤销或内容改变，不恢复、不返回成功分享，要求新的预览和新操作键。明确重新分享才创建新授权。

以下行为在同事务标记相关 active shares 撤销：本人撤销某个分享；连接撤销；移除 care_tasks scope；标题/正文/类型/日期改变。重新连接或重新增加 scope 不恢复旧 shares，即使 FamilyLink 沿用同一行。

撤销确认后开始的任何列表、详情、提醒生成和通知状态更新都必须重新校验数据库，不使用授权缓存；写操作与撤销序列化。撤销前已读取或已传送的内容不能保证召回，UI 如实说明。对于已在途网络响应，客户端在收到撤销/重新加载后移除缓存并拒绝旧 generation 响应，不承诺收回已到达另一设备的字节。

本批不新增长连接/推送机制。在线照顾者任务页可在进入/恢复/手动刷新及前台定期刷新（建议 30 秒）重新授权；授权刷新失败时共享任务内容不可继续作为当前可访问数据显示，给出重试。新请求拒绝后立即移除相应卡片。

## 6. 提醒、缓存和客户端行为

care_service.py 的任务提醒查询改为本人任务或有效 TaskShare；visible 和通知 PATCH 同样重验。历史 CareNotification 不因存在记录而获得访问权；无逐项授权的提醒从返回结果排除，不产生新提醒。

保留通用、无标题正文的系统通知文案。照顾者的本地任务提醒不再由缓存任务提前排程；升级时取消旧版本给当前照顾者账户建立的任务闹钟，再依现有站内收件箱获取授权提醒。本人任务提醒保留。这样避免离线设备在分享撤销后继续按照旧任务排程；不宣称撤回既有系统通知或外部副本。不要借此引入新通知渠道。

登录/退出/账户切换清空共享任务、分享预览、收件人、share 操作键及权限缓存；迟到响应不能填入下一账户。网络发送结果不确定时保留同一操作键重试；内容或收件人改变须重新预览并创建新键。

## 7. UI 流程

1. 确认创建任务后展示“私人任务，只有你可见”，与家庭分享分开。
2. 任务详情提供“分享给家人”；仅列 active 且有 care_tasks 的家庭连接，初始不选择收件人。没有资格时说明需建立相应连接，绝不默认扩大 scope。
3. 预览完整标题、正文、任务类型、日期/时间、收件人显示名与可区分身份，说明“只分享这项任务；对方可查看后续进度，不能修改；不包含私聊或其他任务”。无日期明确显示“尚未设置时间”，不编造。
4. 确认按钮显示发送中并防连点；完成后显示“已分享给 X（站内可查看）”。失败、过期、撤销均提供对应反馈，保留可重试草稿；取消不建立授权。
5. 本人可查看收件人并逐项“停止分享”；确认说明停止未来访问，不能保证收回已保存副本。
6. 照顾者显示只读任务详情，移除“Complete”及其他编辑控件；空态写“尚无逐项分享给你的任务”，不再声称创建任务即分享。
7. 繁中/英文、放大字体、长收件人和长正文保持完整可滚动预览，不用省略号代替确认内容。

## 8. 向后兼容、历史数据和安全默认

上线创建空 task_shares 表及索引；旧任务和既有家庭链接不丢失、不自动转换为分享。缺少逐项记录的旧任务仅本人可见；不能从 care_tasks、创建确认、曾显示于照顾者首页或任务完成状态推断逐项同意。本人可逐项重新确认分享。

新表由现有数据库初始化注册建立，避免修改现有列；须在副本验证 SQLite/PostgreSQL 建表、索引、外键及重复启动。若表/索引或授权查询不可用，服务不能回退到旧宽权限：停止相关功能并返回明确错误，必要时拒绝启动。

旧客户端继续创建、读取/修改本人任务；其照顾者列表收窄、PATCH 他人任务拒绝属于必要安全修正。新客户端配旧服务器必须禁用逐项分享入口，不能以旧 broad list 冒充选择性分享；正式切换期间暂停旧服务进程，避免新旧 worker 同时以不同授权运行。回滚不得恢复旧 broad list/PATCH，必要时临时停用家庭任务。

历史任务提醒保留于数据库的记录不是授权。照顾者升级/登录时取消旧本地任务闹钟；不能保证从离线旧版设备撤回内容或系统通知。数据库留存/审计期限按团队政策另定，本批不猜测期限、不删历史本人任务，也不把审计正文复制成额外任务副本。

## 9. 回归验收

验收使用合成账户和临时数据库，禁用外部模型。实施后的本地验证结果见第 11 节；下表保留设计验收矩阵，不表示 PostgreSQL 或真机场景已实测。

| 场景 | 必须观察的结果 |
|---|---|
| 本人创建任务，已有 care_tasks 链接 | 两名照顾者均看不到；本人可读可改 |
| 只分享任务 T 给照顾者 A | A 只见 T；B、其他长者、游客见不到；源 action/聊天/记忆无泄露 |
| A 直接 PATCH 标题/日期/正文/状态 | 全部拒绝；数据库不变；自身拥有的任务行为保留 |
| 取消预览或未选收件人 | 无 TaskShare、无家庭消息、无通知 |
| 同键重试、并发双击、同键不同请求 | 同请求一条授权；不同请求拒绝；不重复通知 |
| 分享与编辑竞态 | 指纹不一致拒绝，或编辑事务撤销旧授权；不能看到未经新确认的正文 |
| 分享/读取/通知操作与连接撤销竞态 | 撤销提交后新操作拒绝；无有效授权提醒 |
| 撤销单项分享 | A 列表/详情/通知隐藏 T；其他仍有效分享保持 |
| 重新连接/恢复 scope/重放旧键 | 旧授权不恢复；新预览、新键才能重新分享 |
| 只更新本人进度 | A 仍只读，可见进度；正文修改必须重新分享 |
| 原数据库含旧任务/提醒，重复初始化 | 任务仍属本人、无自动分享、无越权提醒；索引约束有效 |
| 模拟 schema 初始化/权限查询失败 | 无旧宽权限 fallback，不输出私有任务 |
| 照顾者客户端升级和退出 | 清除旧本地任务闹钟；迟到响应不能恢复上一账户内容 |
| HTTP 超时及撤销后重试 | 超时不报成功；仍有效同键恢复同 share；已撤销同键不复活 |
| 繁中/英文手机、大字体、长正文/身份 | 完整预览、取消/确认/停止分享可操作，无溢出；照顾者无编辑按钮 |

更新旧 test_family_scope_and_revoke_are_enforced 的“确认即可见”断言，保留私聊不可见及撤销断言。补 tasks API 权限矩阵、care_service/notifications 授权、Flutter 分享预览及账户切换测试；调整现有 live API/设备验收中共享任务的准备步骤，不把改测试当成实现完成。

## 10. 待决、参考文件和自审

待决仅影响后续扩展：照顾者是否可以回应、接受陪同、更新自己的执行进度，以及这些动作是否独立于长者任务状态。本批全部只读，不需猜测。分享和审计的保留期限待团队决定；既有撤销记录在本批保留以防重放，不承诺永久保留。自动偏好变更由父线程单独处理。

reference documents/Untitled Notebook 22.pdf 是原始手绘流程；reference documents/anxin-competitive-analysis.pdf 是竞品背景。现有可读整理为 docs/CURRENT_TASKS_ZH.md、docs/ECHO_REQUIREMENTS_AND_PROGRESS_ZH.md 及 SRS §4、7–18。未独立渲染 PDF，未安装工具；目前未有已核实的 PDF 内容推翻“逐项预览和指定收件人”原则，不把推测当作新要求。

自审结果：
- 区分连接资格、创建确认与逐项分享；无历史自动补授权。
- 只读边界覆盖 HTTP、通知、客户端和旧客户端，不保留照顾者 PATCH 后门。
- 撤销不因重新连接、重复请求或编辑而复活；内容变化需新确认。
- 新表支持现有数据库保留任务，初始化失败安全拒绝，回滚不恢复泄露。
- 站内可查看、已发送、已读、外部副本召回明确区分。
- 没有把来源许可、自动偏好、群聊或新通知架构混入本批。
