# Echo 需求与当前实现说明

**更新日期：2026 年 9 月 28 日**

**用途：**供团队、演示准备和项目评审了解新版需求、已完成的工作与剩余范围。本文是进度说明，不替代完整软件需求规格。

**来源审查补充：**社区两站的既有验收证明技术读取，不代表取得使用许可。JCVTP 条款限制抓取，HKCMIS 的自动再利用许可未确认；默认应用现已停用两站自动抓取，正式使用前仍须按 `docs/ECHO_DEFERRED_FEATURES_FEASIBILITY_ZH.md` 完成来源审批。

## 一 这个项目要解决什么

Echo 面向香港长者，提供一个以长者自主决定为核心的对话与社区参与工具。产品主线是：**对话 → 经本人确认的记忆 → 更贴合个人的支持 → 人际联系与社区参与**。它希望帮助长者理解实际信息、与家人保持联系，并把自己的经验和技能带入社区。它不能代替家人、社工、医护、官方服务或紧急求助渠道。

新版需求以 `reference documents/Echo_Software_Requirements_Specification_v1.1_Corrected (1).md` 为主要依据，并参考队友补充的记忆事项、手绘流程和竞争分析。原本的五个主导航保持为 Home、Family、Community、Help、Settings。竞争分析用于调整功能边界，不等于已验证的长者需求。

## 二 需求是什么

| 需求领域 | 目标行为 | 关键边界 |
| --- | --- | --- |
| 低门槛对话 | 不注册也能问一般问题；有账户后可使用私人功能；回答简短、耐心，必要时给出来源和下一步 | 游客对话不能变成长期记忆；重复提问不能受到责备 |
| 长期记忆 | 默认关闭；长者开启后，逐条查看候选并选择保存、编辑或不保存；可查看、修改和删除已存记忆 | 未确认信息不得用于长期个性化；关闭记忆与删除数据是不同操作 |
| 家庭联系 | 长者批准连接，预览具体内容和收件人后，才分享选定卡片、消息或计划；家人可以回应 | 家人不能读私人聊天或整个记忆库；不能形成持续监控看板 |
| 实用信息 | 用易懂语言解释福利、医疗服务、交通和防骗信息；显示官方来源、日期、不确定点与下一步；可制作独立 Answer Card | 不替官方系统计算路线、诊断、预约、识别来电或报未经核实的实时数值 |
| 社区参与 | 浏览真实活动；从已确认记忆建议技能，由长者确认后寻找相关机会；说明来源、日期和条件 | 不能自动公开技能、报名或联系机构；活动是否仍有名额和用户是否合资格须核实 |
| 人工帮助与易用性 | 明确的求助入口、经核实的转介方式、清晰的大字界面；语音不可靠时仍可打字 | 对外发送须逐次确认；粤语语音、真实机构接入需要另行验证 |

需求中的公共香港记忆地图、开放式互助、真实用户匹配等属于未来或条件性范围。系统也不得默默录音、持续定位、读取病历或通话记录。

## 三 目前做了什么

前一阶段已有长者与照顾者账户、文字对话、私人记忆、家庭邀请与撤销、家庭留言、私人故事选择分享、共享任务、六条经过整理的官方信息记录，以及繁体中文和英文界面。针对新版需求，已经由 GPT-6-luna 子任务分别处理隐私与游客入口、社区后端、Flutter 界面，以及后续的社区在线搜索；主任务负责需求整理、接口协调和独立验收。

这轮工作把基础入口和隐私顺序改为“先能提问，之后再选择是否注册与保存”，并实现了限定网站的自动搜索适配器。因来源许可未明确，默认应用不自动抓取活动；获准后活动内容可由系统更新，而无需团队人工逐条录入。可信网站清单及网页格式变动仍需软件维护。

## 四 已实现并验证的能力

**游客和账户。**游客可以进入对话及查询公共帮助信息，不必提供身份资料。游客会话保存在服务进程内，30 分钟无活动后过期，结束会话后不能恢复；不会写入私人账户、长期记忆或私人对话库。有账户时区分长者与照顾者角色。

**记忆控制。**长期记忆对新旧长者账户均默认关闭。长者明确开启后，新聊天中的记忆建议只随回复暂时呈现，点击 Save 才写入确认记忆。关闭记忆会停止新增、召回及技能发现，但旧记忆仍可由本人查看和管理。照顾者不能替长者开启记忆。现有逐条修改、删除和关联内容撤回仍可用。

**家庭与界面。**长者端已接入 Home、Family、Community、Help、Settings 五个主导航。现有家庭连接、私有故事的选择分享、家庭留言和任务可从界面使用；权限测试覆盖家人不得因此读取私人聊天或未分享记忆。界面保留繁体中文与英文切换。

**社区技能与在线资料。**系统仅从已确认且仍有效的记忆中提出私有技能建议，长者可以确认、修改或拒绝。确认后可按一般技能主题寻找义工机会。社区页面可按主题和地区搜索；游客及登录用户明确要求找活动时，对话也会触发搜索。当前自动读取[香港基督教培道联爱会活动页](https://hkcmis.com/embed?unit_id=3)和[赛马会众心行善平台义工机会页](https://www.jcvtplatform.hk/zh/volunteer-opportunities)。界面显示来源、活动日期、检索状态和可用性提醒；15 分钟缓存、来源故障时最长 6 小时缓存回退，并区分“无匹配”和“来源不可用”。搜索只把一般主题送到公开网站，不发送长者身份或完整私人记忆。

**公开信息。**既有公共资源检索保留六条经整理的官方来源记录，提供来源、条件、仍需确认的信息和建议下一步。它是实用信息的基础，尚不是新版要求的完整、可保存或分享的 Answer Card。

## 五 验证依据与实际范围

截至 2026 年 9 月 27 日的最近一次记录：后端自动测试 **41 项通过**；Flutter 测试 **37 项通过、2 项可选实时测试跳过**，静态分析无问题，常规网页构建成功。第一批隐私与权限独立验收 **34 项通过**。社区真实网站独立验收 **9 项通过**，当次读取到 32 条活动，按烹饪技能筛出 1 条义工机会。网页内容会变化，数字只是该次验收快照，不是固定库存或覆盖承诺。

测试主要使用虚构账户与临时数据库。已经验证两个公开来源可读取及游客、登录对话可保留来源信息；尚未完成实体手机、真实长者、真实报名流程或生产部署验收。默认对话仍使用清楚标识的确定性演示适配器；接入兼容模型的配置能力不等于已经评估了真实 AI 对话质量。

## 六 尚未实现或尚未完整验证

1. **记忆主线补齐。**旧候选接口及旧记忆修正流程仍未全面统一到“保存前不持久化”；新版九类记忆、一次删除全部记忆、完整关闭与删除说明，以及由已确认记忆制作独立 Memory Card 仍需完成。
2. **家庭与分享。**连接请求的拒绝和阻止、Memory Card 逐次分享、与确认计划关联的陪同请求及回应仍不完整。现有故事分享和留言不能直接算作这些新版验收场景全部完成。
3. **实用信息成品。**还需完成带来源、日期、核验状态和下一步的独立 Answer Card，包括保存、打印或只分享该卡；补齐交通、医疗导航、防骗和人工转介的完整引导与官方链接。
4. **社区覆盖。**自动搜索适配器当前只针对两个指定网站，默认均停用；义工机会仅覆盖公开列表页。没有证明覆盖所有香港活动，也没有验证名额、资格或实际报名。由确认兴趣、地点及无障碍偏好生成可解释的完整个性化推荐仍需完善。
5. **语音与真实使用。**粤语语音质量、实体设备可用性、真实模型的香港用语及事实可靠性尚未评估；推送、真实机构外发、公共地图和真实用户匹配未上线。

下一阶段应先补齐记忆的逐条确认与 Memory Card、删除及撤回边界，再完成 Answer Card 与人工帮助路径，并用真实用户和设备验证可用性。每项完成后应按原 SRS 的验收场景重新测试，不能把接口存在或演示数据当作产品验收。
