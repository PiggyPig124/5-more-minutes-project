# SRS §18 Requirement Change Record: Agent-Maintained Preference Memory

- **Requirement ID:** MEM-CR-2026-09-29-01 (affects FR MEM 02, AT 03 and AT 04)
- **Requested change:** When an older-adult account explicitly enables Memory and a configured AI model is available, the model may decide to save an ordinary first-person preference (for example, “我以前喜歡粵劇”) as an active personal memory. It may also identify a correction or a clear request to forget an existing memory. The owner can view automatic-capture provenance, edit, pause or delete each memory. Sensitive and uncertain details require an item-level Save action; quoted, negated and third-party statements must not be auto-saved. Memory remains off by default. Guest and caregiver accounts do not use automatic capture.
- **Reason:** Let the agent maintain useful, low-sensitivity preferences without requiring a separate Save action for each ordinary preference. A previously saved interest can later support a relevant, transparent Community question such as “你之前提過粵劇；想唔想看看有沒有相關活動？”
- **Effect on privacy and safety:** This changes the FR MEM 02 explicit-Save rule for ordinary preferences only, so it requires team review. After Memory opt-in, the configured model receives the current message and owner-scoped active-memory context and returns structured memory actions with a supporting user-text quote. The server validates the action, evidence, owner, current memory version and a bounded sensitive-content veto before writing. These checks reduce risk but cannot guarantee that a model will classify every sensitive or uncertain statement correctly; a real-provider privacy and quality review is still required. Auto-saved preferences carry source-message provenance, remain owner-only, and are excluded from automatic Community skill suggestions. Deletion, pause and correction block silent relearning of the affected topic. Turning Memory off prevents new capture, retrieval and Community prompts. The Community offer is metadata only, appears at most once per memory when a later turn is relevant, and does not trigger a provider lookup. Live event lookup still depends on separately approved source work.
- **Effect on design, development and testing:** Replace rule-based preference extraction with model-authored structured save, suggest, correct and forget decisions. Store a model-proposed topic key for deduplication, correction, deletion protection and Community prompts without parsing memory prose. Keep explicit manual saving and confirmation. With no configured model, the deterministic demo does not auto-save or offer regex-derived memory suggestions. Automated tests use mocked model decisions to cover indirect phrasing, paraphrase, correction, forgetting, provenance, Community prompting, sensitive misclassification, unsupported evidence and invalid memory IDs; backend tests do not establish real-provider semantic quality. Live-model evaluation with representative Cantonese/Chinese/English conversations remains outstanding.
- **MVP or Future Scope classification:** MVP candidate, contingent on team review. Live Community event search for arbitrary interests remains future work until an approved source path is available.
- **Team approval status:** **Pending team review.** Product-owner authorization for ordinary preference auto-save was recorded on 2026-09-29; this does not replace the explicit team review required by SRS §18.
